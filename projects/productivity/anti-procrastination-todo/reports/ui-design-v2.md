## 0. 设计结论

**设计命题**：反拖延产品要降低“开始前的认知和情绪阻力”，而不是用强提醒、大量列表或复杂仪表盘证明自己能提高效率。

本版采用 **Calm Focus / 安静地开始** 视觉与交互体系：暖白留白、深绿清晰的行动按钮、柔和的过程提示以及允许随时退出的任务尝试。它是一款启动辅助工具，不是医学治疗或生产力疗效证明。

**需要做到的四件事**：
1. 新用户打开产品，能够一眼识别“这里该输入什么”，不先配置项目、标签或账号。
2. 将心理阻力选择变成具体且可跳过的**描述性选择卡**；用户的第一步可自由改写。
3. 计时是可控的辅助，不是打卡惩罚；隐藏倒计时、暂停和提前结束有清晰入口。
4. 回顾页明确区分“完成第一小步”与“完成整件任务”，不存在用户未授权的自动完成。

## 1. 问题诊断与改版策略

| 旧版痛点 | v2 处理 | 预期产品价值 | 验证方式 |
| --- | --- | --- | --- |
| 首页任务、辅助说明、隐私提示同层级 | 左侧任务输入为绝对主视线；右侧为次要方法说明，移动端后置 | 减少首次使用找入口的耗时 | 首次任务完成率与眼动/走查 |
| 卡点像普通短标签，文义不充分 | 5 类带细节描述的选择卡 + 全宽跳过 | 帮用户快速理解而不自我诊断 | 可用性访谈、跳过率 |
| 用户不清楚“第一步”是否会被自动改写 | 单独的可编辑 Step 编辑区、字数计数、人工确认按钮 | 增加可控感，减少“AI 替我决定”不信任 | 编辑后保存的 E2E |
| 多页面之间缺少连续的行动路径 | 4 段提示：找到卡点 → 确定小步 → 开始行动 → 温和回顾 | 让下一步可以预期，同时不过度复杂 | 路径完成时间和退出点 |
| 计时与完成语义容易混淆 | 环形显示**本次尝试**的时长比例，不能代表任务完成度 | 降低错误期待 | 理解测试：计时结束≠任务完成 |
| 部分回顾结果语气/视觉含糊 | 4 张独立结果卡，明确说明可能只是部分进展 | 中断后仍愿意返回 | 未开始后 7 日再次尝试率 |
| 无完整明/暗外观偏好 | 语义色变量 + 本地持久化深色模式切换 | 改善不同环境阅读体验 | 主题切换/刷新回归 |
| 移动端重点按钮可能不够醒目 | 320/375px 主按钮满宽，触控高度 ≥48px | 减少误操作 | 视口/触控 QA |

这些都是**设计假设**。自动化测试只能检查实现一致性；是否真正降低拖延，需要真实用户和对照实验。

## 2. 信息架构：首屏只要求一个决定

### 2.1 六种界面状态

| 状态 | 用户主要问题 | 一级操作 | 可退出/次级操作 |
| --- | --- | --- | --- |
| S0 / S1 待开始 | 今天哪件事最难开始？ | 输入难事 → 帮我开始 | 粘贴多行、编辑/归档、设置 |
| S2 卡点 + 起步建议 | 是什么阻止我开始？ | 选择/跳过卡点、改写第一步 → 确认 | 换一个建议、自己写、回清单 |
| S3-准备 | 我可以承诺多小的一段时间？ | 选 2/5/10 分钟 → 开始 | 返回改写 |
| S3-进行 | 现在只做哪一步？ | 暂停 / 继续 | 隐藏计时、结束并回顾 |
| S4 温和回顾 | 这一小步发生了什么？ | 记录四类实际结果 | 返回清单，后续恢复 |
| S5 数据与设置 | 我的数据在哪里？ | JSON 导出、主题切换 | 删除本地数据、了解隐私 |

四阶段导览并非可点击的“流程导航”：它用语义化 \`nav + ol\` 和 \`aria-current="step"\` 指明当前阶段，不制造假按钮。

### 2.2 任务与步骤不变量

- \`Task\` 是母目标，\`Step\` 是可开始的动作，\`Session\` 是一次尝试。
- \`step_done\` **只标记 Step**，用户显式确认 \`task_done\` 才完成 Task。
- 用户修改候选建议后，切换卡点/换建议必须征询覆盖同意。
- 刷新与跨标签操作不应产生重复进行中会话；数据以 IndexedDB 成功提交为准。
- 计时到点不会自动结束/判定完成；隐藏计时只隐藏视觉提示，不改变保存语义。

## 3. 视觉系统

| 设计 Token | Light | Dark | 使用 |
| --- | --- | --- | --- |
| Canvas | \`#f7f7f2\` | \`#101c19\` | 页面背景，低刺激 |
| Primary surface | \`#fffefb\` | \`#1a2b25\` | 任务卡、编辑卡 |
| Heading ink | \`#142c24\` | \`#f3f7ec\` | 信息层级 |
| Primary action | \`#235944\` | \`#c8e5ac\` | 唯一主 CTA |
| Selected / support | \`#e4f0c8\` | \`#2d4837\` | 已选卡点、小步提示 |
| Border | \`#d8e2d8\` | \`#415a49\` | 结构分隔 |

中文使用系统字体及本地中日韩字体回退，**没有外部字体请求**。页面背景使用 CSS 轻量渐变，不需要图片 CDN。常用间距 8/12/16/24/32px，主交互高度以 48～56px 为基准，圆角以 12～24px 为主。

颜色只是视觉辅助：选中还需文字/对勾，暂停有独立状态文案，错误保存必须显示明确文本。

## 4. 关键交互规范

### 4.1 首页：输入成本最低

桌面采用两栏构图，输入卡包含“今天最难开始的是什么？”、低压力示例、强主按钮；侧栏说明“写下难事 → 缩小第一步 → 从两分钟开始”。

移动端将输入、待开始清单保持在最上方，方法说明后置。空状态用鼓励建立第一件任务的文案，不伪造完成统计。

### 4.2 卡点与第一步：用户保留决定权

5 类阻力：事情太大、不知道第一步、担心做错、没精力、容易分心。第 6 个选项“跳过”具有同等可用性；不会推断用户心理诊断。

选择卡以按钮呈现，保留 \`aria-pressed\` 状态。第一步编辑区实时显示字数 \`N / 160\`；建议标注可改写；规则版本可见。页面视觉重心应落在**确认自己的第一小步**，而不是调整列表优先级。

### 4.3 计时：可见但不施压

环形进度只表示当前会话的时间比例；暂停/继续与结束并回顾保持显著。倒计时可以隐藏，屏幕阅读器不会每秒播报数字。页面隐藏/刷新时，不会把不可观察的后台时间计为真实专注。

### 4.4 回顾：减少“失败感”

四个选项：第一小步完成 / 做了一部分 / 还是没能开始 / 整件任务已经完成。第一步完成以柔和强调色呈现，但**不将“没开始”做成红色错误卡**。最后一个选项需要二次确认。

### 4.5 设置：可信的数据边界

主题仅保存在当前浏览器的外观偏好中。任务正文只存 IndexedDB，默认无遥测上报。JSON 导出不是可恢复备份：**P0 尚不支持 JSON 导入**，不能宣传为完整灾备方案。

## 5. 响应式与无障碍设计

- **1440px**：两栏首页；卡点页面是主卡 + 辅助说明。
- **790px 以下**：首页转为单列主体，方法说明移至后方。
- **560px 以下**：主 CTA 满宽、任务操作换行、卡点卡片可触控、回顾单列。
- **320/375px**：必须没有横向滚动；首屏输入/提交按钮可操作。
- **焦点**：键盘交互控件始终显示明确焦点指示；程序化聚焦标题可以为屏幕阅读器提供方向，但不应出现与输入控件混淆的大面积焦点框。
- **Skip link**：键盘可聚焦的“跳到主要内容”链接在未聚焦时应视觉隐藏，聚焦后恢复；不能因为截图滚动而意外暴露。
- **Reduced motion**：遵守 \`prefers-reduced-motion\`，取消装饰动画/过渡。
- **WCAG**：以 WCAG 2.2 AA 为设计目标，尚未通过独立的读屏、键盘全流程、颜色对比与浏览器矩阵人工审计。

## 7. 评价指标与发布门槛

**自动检查**：主要 CTA 存在且可触达；无横向溢出；卡点选中和 textarea 字数状态一致；隐藏计时不丢 session；主题切换后本地任务仍在；步骤完成不自动完成母任务。

**人工检查**：至少覆盖 iOS Safari、Android Chrome、Firefox；至少一次读屏+键盘可用性检查；颜色对比和 200%/400% 缩放；异常存储失败恢复。

**用户验证**：用真实目标用户评估“从打开应用到第一次行动”的阻力，记录焦虑/压力负反馈；在预注册的对照实验前，不得用 UI 审美偏好代替实际启动率改善证据。
