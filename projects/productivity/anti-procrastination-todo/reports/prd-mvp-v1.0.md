## 1. 背景与问题定义

### 1.1 用户真正的困难

已记录的任务并不天然变得易于行动。典型体验是“整理任务 → 觉得任务巨大/害怕做错 → 打开其他网页 → 任务继续搁置 → 下次看到清单更有压力”。传统工具通常优化输入、分类、优先级和提醒，却未必帮助人度过开始前最难的一分钟。

Start-First 假定一次成功的使用不是“新增一个 TODO”，而是**用户针对一件有阻力的任务，自己确认一个小而明确的真实动作，并开始尝试**。

### 1.2 目标用户与排除人群

**Primary persona：已经有清单却启动困难的人。** 每周 2 次以上遇到重要但反复回避的任务；能说出任务名称，却不知道第一步、担心失败或疲劳；可能使用 Todoist、TickTick、Notion、纸笔或聊天软件。愿意使用简短辅助，但不愿迁移完整任务库。

**Secondary persona：任务太大而难以落地的人。** 例如写论文、准备面试、报税、回复困难邮件。适合短动作拆解和恢复机制，但不是专业心理/医疗用途。

**暂不服务：** 需要多人协作、复杂项目依赖、企业合规、治疗建议、严格时间追踪、上百条任务的项目管理用户。拒绝用“患病”“懒惰”来描述用户。

### 1.3 Jobs to be Done

> 当我明明知道必须做某件事，却一再绕开它时，我想尽快找到一个不会吓退我的第一步，并允许自己只做一点点，这样我不用在复杂计划或自责里继续耗时间。

用户希望：被理解但不被诊断；有具体动作而不是泛泛鸡汤；可以拒绝建议；即使中断也能毫无负担地回来；自己的任务不会消失。

## 2. 产品目标与非目标

### 2.1 目标（以可观测行为表述）

1. 新用户在首次打开后，不登录即可建立一个“当前难事”。
2. 在不强迫用户接受建议的前提下，将任务变为可编辑、具体的第一动作。
3. 用户可以快速开始 2/5/10 分钟尝试，而不需要先配置项目、截止日或标签。
4. 允许中途暂停、结束或缩小目标；恢复时不羞辱、不补罚任务。
5. 在设备本地持久化任务与会话，刷新/退出再打开可以恢复和导出。
6. 用有边界的行为指标判断产品是否有帮助，严禁把按钮点击当成真实生产力。

### 2.2 本期明确不做

- 不做完整 Todoist 克隆：无标签树、子任务层级、循环规则、项目依赖、批量优先级自动排程。
- 不做账号体系、云同步、多人协作、实时日历读写、外部服务 OAuth。
- 不做必须联网的 LLM 拆解；P0 以可解释模板生成小动作，P1 可做受控 AI 实验。
- 不做摄像头监督、强制锁机、惩罚弹窗、连胜损失、公开排名或推送轰炸。
- 不承诺焦虑/ADHD/拖延症治疗效果；无医疗诊断、个性画像及治疗方案。

## 3. MVP 产品原则

1. **先行动，后组织**：首次使用不要求建分类、填截止日或整理 backlog。
2. **一个屏幕，一件事**：执行页面聚焦当前动作，仍可随时返回/查看列表。
3. **建议可以被拒绝**：第一步必须可改写、跳过、更换；不以 AI/模板建议代替用户判断。
4. **失败可恢复**：中断不是失败；没有红色欠账、羞辱文案、强制连续打卡。
5. **不依赖计时产生焦虑**：支持隐藏倒计时、关闭提示音，停止不会被惩罚。
6. **信任优先**：每次修改可回退，数据生命周期清晰，导出和删除在设置中可找到。
7. **隐私默认保护**：无需账户，任务正文默认只保存在当前浏览器；行为实验必须独立授权。

## 4. 用户旅程与信息架构

### 4.1 核心闭环（黄金路径）

1. **捕获**：用户输入“准备明天的客户汇报”；也可从其他清单复制多行文字导入。
2. **选定**：在“待开始”队列点击这一条；界面隐藏其他事项，只保留当前任务。
3. **识别阻力**：选择“事情太大 / 不知怎么做 / 担心做错 / 没精力 / 容易分心”，可跳过。
4. **生成起步动作**：规则模板给出“打开演示文稿，写下汇报要回答的 3 个问题”；明确标为建议。
5. **确认或修改**：用户可将其改为“先写首页标题”；不强迫完成整个母任务。
6. **开始尝试**：选择默认 5 分钟（可选 2、10），点击“开始这一小步”。
7. **结束或暂停**：标记“第一步完成 / 做了一部分 / 还没开始 / 下次继续”，记录实际感受。
8. **温和恢复**：若未完成，允许将动作再缩小；任务保留，用户随时重新启动。

### 4.2 页面（最小 IA）

| 页面 | 首要职责 | 主操作 | 次操作 |
| --- | --- | --- | --- |
| S0 欢迎/即时捕获 | 不阻断首次使用 | 输入一个困难任务 → 继续 | 查看如何工作、隐私说明 |
| S1 待开始 | 记录并选择当前难事 | 开始某个任务 | 单/多行粘贴导入、编辑、归档、导出 |
| S2 卡点 → 起步动作 | 帮助从模糊到具体 | 确认小动作 | 选择/跳过卡点、改写/换一个建议 |
| S3 短行动会话 | 让用户进入真实工作 | 开始/暂停/继续 | 隐藏计时、结束、切换任务（需确认） |
| S4 温和回顾 | 正确记录尝试结果 | 保存结果 → 返回 | 缩小动作再试、标记母任务完成 |
| S5 设置与数据 | 可信保存与自主管理 | 导出 JSON | 导入备份（P1）、删除本地数据、隐私开关 |

**导航规则**：无底部五栏式重导航；主页面最多两个显著行动点，避免重新制造整理负担。优先支持键盘、触控与屏幕阅读器。

### 4.3 状态层次

- **任务 Task**：inbox → active → done / archived；归档不等于完成。
- **起步动作 Step**：draft → ready → attempted → completed / carried_forward；第一步完成不代表母任务完成。
- **会话 Session**：idle → running ↔ paused → ended；ended 需选择结果，允许仅记录“尝试过”。
- 单设备只允许一个 running 会话；当新会话启动时，明确询问先结束/暂停旧会话，不静默覆盖。

细节、字段、转换约束和异常恢复见[功能规格](mvp-functional-spec-v1.0.md)。

## 5. MVP 功能范围与优先级

优先级定义：**P0 = 必须具备才能进行效果验证；P1 = MVP 通过门槛后实验；P2 = 不在首发范围**。

| ID | 功能 | 等级 | 用户价值 | 首版边界 |
| --- | --- | --- | --- | --- |
| F01 | 零登录快速捕获与多行粘贴 | P0 | 降低开始前录入阻力 | 纯文本，单次最多 20 行；无附件 |
| F02 | 当前难事单任务视图 | P0 | 避免被整个 backlog 吓退 | 最多一件 active；用户可退出聚焦 |
| F03 | 五类阻力识别（可跳过） | P0 | 用更合适的方式处理卡住 | 无临床标签/用户画像 |
| F04 | 规则式起步建议 + 自由编辑 | P0 | 将任务转为 2～5 分钟动作 | 轻量模板，不生成事实性专业建议 |
| F05 | 2/5/10 分钟短会话 | P0 | 给出低门槛开始动作 | 计时可隐藏、暂停、退出；不限制其他 App |
| F06 | 温和回顾与恢复 | P0 | 中断后仍愿意回来 | 步骤/母任务区分，四种结果 |
| F07 | 本地保存、撤销、JSON 导出/删除 | P0 | 任务可靠、隐私可信 | 单设备单浏览器；无跨端同步保证 |
| F08 | 访问与实验的基础埋点 | P0* | 衡量效果与可靠性 | *仅在自愿同意下发送匿名结构化事件；不采集任务正文* |
| F09 | LLM 个性化建议/原因解释 | P1 | 提升建议适配性 | 单独开关、清晰数据提示、降级为规则模板 |
| F10 | 可恢复备份导入、PWA 离线安装 | P1 | 跨会话可持续 | 无跨设备自动同步 |
| F11 | 日历、Todoist/TickTick/Notion API | P2 | 接入既有任务源 | 权限和回写需单独设计 |
| F12 | 成就积分、社交监督、自动优先级 | P2 | 或可提升黏性 | 先验证启动价值，防止喧宾夺主 |

### 5.1 关键业务规则

- 任务正文必须经过用户确认才保存；清空文本不得创建空任务。禁止静默自动拆分一项为多项。
- 建议是待确认的候选；用户编辑后必须保留用户版本，不得被刷新重写。
- 默认计时 5 分钟；到时仅提供“继续 / 结束并回顾”，不得自动把母任务标为完成。
- 不完成时**不累积欠账、不延长计时惩罚、不替用户更改重要性**。
- 结束回顾可以保存“尚未开始”；这个结果与“第一步完成”分开统计，防止虚假成功率。
- 存储失败必须展示“未保存”或重试，不得假装成功；任何删除动作提供二次确认。
- 用户可不参与产品分析；不影响捕获、启动、结束、恢复的功能可用性。

## 6. 关键功能设计（产品级）

### F01/F02｜快速捕获与选定当前难事

**触发**：第一次来、拖延发生时、从已有任务工具复制文字时。  
**输入**：1～200 字任务标题；可选补充说明最多 1,000 字。粘贴多行默认按行拆分，先展示预览让用户确认。  
**结果**：任务进入本地 inbox；选中一项进入聚焦页，其他任务隐藏但不丢失。  
**异常**：超限提示截断预览并允许编辑；重复标题不自动合并；存储容量不足不可声称“已保存”。

**验收**：首次访问无需账号可以完成捕获；粘贴 5 行可逐条确认；修改后刷新仍可找回；归档与完成分离；键盘可用。

### F03｜识别卡点

**触发**：点击“帮我开始”，并非强迫新建时填写。  
**选择**：事情太大、不知怎么做、担心做错、没精力、容易分心；仅单选，附“暂时说不清/跳过”。  
**输出**：用于选择本地建议模板，不推断心理诊断，不进行隐含敏感画像。  
**验收**：两步内可跳过；更改原因能刷新候选建议但**不能覆盖已手改动作**。

### F04｜第一步生成与人工改写

**触发**：用户确认任务与卡点。  
**输出**：1 个简短且可实际执行的小动作，避免“完成报告”“努力起来”等伪动作；如含无法确定的客观事实，应转化为“先查找资料/打开空白文档”等可控动作。  
**用户权利**：编辑、重新建议、直接自填、仅保存不计时。  
**验收**：空白/错误建议都有兜底；保留用户输入；未选原因也能开始；不得将候选假装为已执行事实。

### F05｜短行动会话

**触发**：用户点“现在开始”。  
**默认**：5 分钟；2/10 分钟选项；单一清晰 CTA；无强制通知或网页屏蔽。  
**控制**：暂停、继续、手动结束；计时显示可隐藏；页面刷新后恢复计时与当前步骤，不重新记一次启动。  
**验收**：同一时刻最多一个 running；重复点击只产生一个会话；结束动作进入回顾且保留状态。

### F06｜回顾、退出与恢复

**结果选项**：“第一步完成”“做了一部分”“没能开始”“母任务已完成”；允许用户不填写文字理由。  
**交互语气**：“没关系，可以缩小这一步再试”，而不是“你今天失败了”。  
**下一步**：若完成第一步，提示可继续另一小步或返回；若未开始，给出更小步骤入口；若母任务完成，只有用户主动选择才更改任务状态。  
**验收**：未完成不扣分；再次进入可从上次动作继续；所有结果可更正。

### F07/F08｜可信存储和隐私边界

**模型**：默认设备本地 IndexedDB，原子事务保证任务/步骤/会话一致；必要时提供“不支持持久存储”的降级说明。  
**边界**：本地存储不等于云备份；浏览器清缓存、隐私模式、设备损坏可能导致数据永久丢失，界面应明确告知并支持 JSON 导出。  
**遥测**：仅在明确同意后发送动作类型与时间/耗时区间、匿名随机安装 ID；不上传任务文本、生成的小动作或敏感自由输入；用户可以随时撤回。  
**验收**：刷新、离线、重复点击、写入失败均有可观察处理；可导出、删除；撤回同意后不再发事件。

## 7. 成功指标与测量口径

### 7.1 北极星：困难任务的合格启动率（Qualified Difficult-Task Start Rate）

**分母**：进入队列并被用户标记为“难以开始”的去重任务（分析期为创建日起 7 天；若同一任务反复尝试只算一次）。**分子**：这些任务中，在创建后 24 小时内出现一次满足“用户主动启动且实际处于 running 累计 ≥60 秒，或用户显式标记第一步完成”的尝试。重复开关不重复计数。

该指标是**可观测行为代理**，不能证明用户真正投入了注意力，更不能推断临床效果；应与访谈/任务日志联合判断。

### 7.2 辅助与守护指标

| 指标 | 明确定义 | 用途 |
| --- | --- | --- |
| Time to first action | 从任务创建到第一次会话真正开始的中位耗时；剔除缺失/无启动并同时报告未启动比例 | 看启动摩擦 |
| First-step acceptance | 候选建议被原样接受 / 展示过候选建议的任务数；同时记录编辑率 | 看模板适配度；越高不必然越好 |
| Recovery rate | 用户报告“部分/未开始”后 7 天内再次尝试的任务占比 | 看容错是否促进回来 |
| W1 reuse | 新设备安装 cohort 在第 2～7 天再次开始会话的比例 | 观察早期复用，不等于长期留存 |
| Loss/duplication incidents | 可复现的任务丢失、重复会话、错乱状态次数及影响用户数 | 必须为发布阻断项 |
| Pressure complaints | 访谈反馈“提示令人焦虑/被催促”的人数与典型场景 | 负面体验守护 |
| Opt-in rate | 有效同意数据收集的比例，并报告样本选择偏差 | 防止把匿名样本误作所有用户 |

**指标实现前提**：若未获得同意，不能上传遥测；通过匿名参与者访谈/自愿导出数据取得离线反馈，所有自动分析均附“仅覆盖同意者”的说明。

### 7.3 预注册建议性决策门槛（不是已有成果）

- **可用性试验**：招募约 12–15 位目标用户完成典型场景；目标 ≥80% 在不被提示下成功完成“从任务到短会话”；任务理解歧义集中点必须修正。小样本不做显著性推断。
- **可靠性门槛**：P0 测试矩阵中无已知可复现的 P0 数据丢失/静默失败、错记完成、重复 session 问题；高优先级缺陷关闭后才邀请外部测试。
- **行为试验**：对自愿参与者在同类困难任务上比较“普通任务输入+开始按钮”与“识别卡点+第一步+短会话”；随机分配实验单元并提前确定分母和分析窗口，报告效应大小/区间而非只看 p 值。
- **继续投入的信号**：至少有方向一致的启动率提升、无明显焦虑/失信副作用、有可复述的高价值使用场景；否则优先改进定位而非新增功能。
- 不预先宣称“提升 30% 生产力”，也不据 1–2 周样本宣称 PMF。

## 8. 页面与体验规格

### 8.1 文案体系

- 主 CTA：**帮我开始 / 开始这一小步**；不用“征服拖延症”“立即变高效”。
- 卡住时：“先做一点也算开始”；但避免机械鼓励和虚假心理承诺。
- 计时结束：“这段时间你做到了哪一步？”而非“任务已完成”。
- 本地保存：“此设备已保存。换设备或清除浏览器数据后可能无法恢复，建议导出备份。”
- 异常：“保存失败，当前修改尚未写入本地；请重试或复制内容。”不能给虚假成功反馈。

### 8.2 无障碍、性能与响应式

- 320px 宽以上移动屏优先；桌面最大阅读宽度建议 720–880px；可用键盘完整操作。
- 基于 WCAG 2.2 AA 设计：语义化标签、焦点可见、文本对比度、可暂停动画、屏幕阅读器状态提示；不要仅靠颜色表达“运行/暂停”。
- 不因倒计时自动夺焦点；时间结束可视觉提示，音效与通知默认关闭。
- 首屏不加载营销视频或大型框架；低端手机与弱网下仍可录入、查看和恢复本地任务。

## 9. 技术与交付边界（不锁定具体框架）

**架构建议**：静态/边缘托管 Web 应用 + IndexedDB 本地持久化 + 可选匿名遥测 endpoint；领域模型分 Task/Step/Session/Consent，状态转换必须可测试。离线可用属于 P0 的“已加载应用刷新/恢复”；PWA 安装与跨设备同步不是 P0 承诺。建议增设 schema version 和迁移机制，确保未来版本不静默破坏旧数据。

**安全与隐私**：不上传任务正文；禁用第三方广告追踪；开发/错误日志不得包含任务标题；CSP、依赖审查、输入转义、导出 JSON 类型校验；任何共享计算或 AI 调用必须先获得单独明确授权。对于本地数据库的浏览器驱逐风险，提供说明并鼓励导出。服务器不保存自由文本，除非未来通过单独 PRD 修订。

**定义完成（DoD）**：每个 P0 需求具备清晰状态/接口约束、前后端可自动测试的逻辑、错误提示、埋点事件设计、可访问性检查和可复现验收步骤；数据安全阻断项不得豁免。

## 10. 假设、风险与依赖

| 风险 | 早期预警 | 应对 |
| --- | --- | --- |
| 看起来像普通番茄钟，差异不足 | 用户直接跳过阻力识别，不愿重复使用 | 测试“起步动作”是否比简单计时带来增量价值 |
| 规则建议空泛或不适合情绪性任务 | 建议编辑率高，用户评价“还是不知道做啥” | 强化任务类型与用户例子，允许完全手工编辑；暂不引入必需的 AI |
| 计时引发压力 | 不愿开始、常关计时、负面访谈 | 默认温和语言，计时隐藏/改成正计时作为 P1 实验 |
| 本地数据丢失、浏览器驱逐 | 导出/恢复求助、QA 发现写入异常 | 原子写入、错误显式显示、导出提示、版本迁移和异常恢复演练 |
| 点击会话未代表真实工作 | 只有计时无可举证的动作 | 自报完成度 + 随机访谈 + 对照组，不用计时独自证明有效 |
| 早期人群太宽 | 学生、职场用户反馈两极分化 | 优先聚焦“困难写作/邮件/准备工作”场景做访谈 |
| 过度依赖社区反馈 | 调研样本集中于技术用户 | 招募社区外目标人群，按场景分层 |

**依赖**：需明确隐私政策负责人、用户访谈与 QA 所有人、是否部署匿名遥测服务器；没有这些条件时依然可以发布本地应用，但不能进行自动化行为对照分析。

## 13. 开放问题（上线前需给出明确答案）

1. 同一个“困难任务”是否默认保留多条历史起步动作？**建议是**，但新一轮只展示最近一条。
2. 对“担心做错”给出的“写一份不会发送的草稿”，是否在用户数据语义上足够安全？**需做体验访谈**。
3. 没有服务端时如何为研究招募用户提供可回收的匿名实验数据？**建议单独同意 + 结构化事件端点**；否则使用本地导出参与访谈。
4. 多行粘贴产生的重复项是否允许一键撤销整批操作？**建议 P0 支持同批撤销**。
5. 再次打开应用时是否自动显示“上次卡住的那一步”？**建议提示恢复，但不强制启动**。
6. 发布地区、语言与隐私/无障碍法律要求需由负责人根据实际运营地评估；本 PRD 不做合规认证声明。
