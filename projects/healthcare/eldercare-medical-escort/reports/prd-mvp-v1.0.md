# 老龄社会可信陪诊平台 — 产品需求文档（PRD v1.0）

> **文档编号** EM-PRD-001 · **版本** v1.0 · **日期** 2026-11-09 · **状态** Proposed / 待行业、法律、保险和实地试点验证  
> **研究依据** [陪诊行业深度调研](research-2026-11.md) · **开发验收** [MVP 功能展开规格](mvp-functional-spec-v1.0.md) · **项目入口** [README](../README.md)  
> **说明**：本文是产品设计提案，非已经上线、获批、取得医疗合作资质或完成用户验证的产品。示例价格和阈值为假设。

## 0. 决策摘要（Executive decision）

**一句话定位**：帮助因异地、工作或照护安排无法亲自到场的成年子女，为具有自主决策能力、无需专业医疗护理的父母安排 **规范、可追踪、能够人工应急的常规门诊陪诊服务**。

**核心价值**是“确认有人按时到场，陪老人完成非诊疗事务，家属在被授权的范围内知道进展和后续待办”，而不是“帮人抢号”或“AI 看病”。MVP 不建设全国化撮合市场，而是在 **单城、2–3 家相邻医院、受控陪诊员团队** 完成最小真实付费闭环；软件是履约工具，安全与线下服务体系是产品的一部分。

### 0.1 四项不可妥协的设计原则

1. **患者本人为服务与健康信息决定的中心**：子女付款 ≠ 父母同意共享全部诊疗信息；服务同意、数据处理、家属共享分别授权，且可撤回。
2. **安全优先于成交**：不适合非医疗陪诊的高风险订单须拒接或转介；任何工作人员不能诊断、建议更改用药、代签医疗同意书。
3. **可解释、可追责、可替补**：报价、人员、集合地点、节点进度、异常、改派、退款均有明确责任人和审计线索。
4. **先运营、后自动化**：人工筛选和调度主导；算法可建议但不得绕过风险门槛或服务边界。

### 0.2 项目阶段与决策门禁

| 阶段 | 交付与判断 | 当前状态 |
| --- | --- | --- |

## 1. 机会与证据边界

调研报告汇总了中国老龄化数据、上海浦东及南京服务案例、Hacker News / Product Hunt / Reddit 讨论以及 GB/T 47801—2026。能支持的结论：真实存在“院内陪同不等于网约车、家属需及时获得可靠信息、人员爽约和收费不透明会侵蚀信任”等问题；**不能**支持全国付费渗透率、可复制利润或现有产品市场契合度（PMF）已获证实的声明。参见 [研究原文](research-2026-11.md) 及其 31 条来源。

### 1.1 价值假设（可证伪）

| 编号 | 假设 | 试验方法 | 否证信号 |
| --- | --- | --- | --- |
| H1 | 成年子女愿意为可信、准时、记录清楚的陪诊支付合理费用 | 真实报价、订单、退款及复购追踪 | 访谈认同但没有实际付费 |
| H2 | 老人愿意接受经过介绍、尊重隐私的陌生陪诊员 | 本人访谈、预约前电话确认、服务后独立回访 | 高比例拒绝、恐惧或投诉 |
| H3 | 单城少量医院的集中调度使人员综合工时和服务质量可控 | 记录从出门至回程总占用与待命率 | 交通和空档吞噬全部毛利 |
| H4 | 家属授权共享 + 规范节点报告能降低焦虑和售后成本 | A/B 或受控前后对照，观察询问、投诉 | 频繁通知反而导致误解 |
| H5 | 真实社区/机构渠道较纯投放具备更可持续 CAC | 按来源记账、对比 CAC 和实际客单 | 渠道无有效线索或导流不合规 |

## 2. 用户画像及 JTBD

| 角色 | 优先级 | 核心任务 | 关键约束 |
| --- | --- | --- | --- |
| P0 成年子女/付款人 | 首个获客对象 | 异地完成预约、确认人员、支付、在授权范围内看进度、接收后续待办 | 无权默认调取老人健康信息 |
| P0 老人/服务对象 | 唯一现场服务中心 | 有尊严、不迷路、不被骗地完成常规门诊 | 可拒绝某项服务、拒绝录音、撤回共享 |
| P0 运营调度员 | 履约组织者 | 风险判断、报价、派单、备援、监测迟到、异常响应 | 不进行医疗判断，必须有升级机制 |
| P0 核验陪诊员 | 服务执行者 | 识别老人、陪同候诊和非医疗流程、记录原话、及时汇报 | 不代签、不收回扣、不提供临床意见 |
| P1 客服与质检 | 保障服务质量 | 回访、投诉、退款、事故复盘、人员培训改进 | 按最小必要原则访问数据 |
| P2 合作机构 | 未来渠道 | 合规服务采购、进度与对账 | 首版不承诺医院官方接口或合作资格 |

**首个用户旅程**：工作日无法陪同父亲复诊的成年子女在前一天预约，老人本人接到服务说明并同意陪诊；平台确认无临床护理需求，提供完整报价与集合方式，分配核验陪诊员。服务当日工作人员按时到达，按医院允许的流程协助候诊、缴费、取药；家属仅收到老人同意共享的状态与事项。服务结束后人工回访，双方能查询账单、提出异议或申请退款。

## 3. MVP 范围、边界与服务品类

### 3.1 首期服务

- **标准陪诊（P0）**：常规门诊，协助集合、导航、排队/候诊、窗口办事、缴费与领取报告/药品、按院方规则陪同检查流程、记录经授权的医嘱原文与诊后事项。
- **适老预约支持（P0）**：电话预约由人工录入；不要求老人安装 App。
- **远程家属协同（P0）**：仅在适当授权范围内发送进度；必要时由老人同意接通子女电话，不保证诊室录音/直播。
- **加时/接送（P1）**：若未来开展，单独报价和合同；有交通运输许可或专业转运要求的服务只能由适格主体承担。
- **复诊连续协同（P1）**：同一家庭后续复诊提醒、在老人同意下优先使用熟悉陪诊员。

### 3.2 不接受/需专业人员另行评估的场景

初期**不承接**急症、需实时临床监护、意识不清或严重认知障碍且无适格监护/照护安排、需专业搬运转运、术后麻醉高风险接送、人员无法保障安全的独立转移等情况。特殊风险由经培训的人工筛选和专业意见决定是否应转介，不由 AI 自动放行。突发紧急危险时立即依据现场情况联系医院急救及 120，而不是通过平台继续派普通陪诊员。

### 3.3 明确排除

医疗诊断/咨询、检验结果解释、处方与用药建议、代签医疗文书、抢占/倒卖号源、承诺加号、未经许可的诊室录音录像、医院系统数据爬取、即时全国调度、自动保险理赔、复杂会员预付体系、AI 自主派单或自主医疗判断。

## 6. 核心业务闭环

```text
家属/老人发起预约
  -> 地域与服务适配初筛
  -> 人工风险复核（不适配则拒接/转介）
  -> 老人知情同意 + 合同 + 可选家属共享授权
  -> 明细报价确认、支付（或经批准的人工支付）
  -> 调度指派合格陪诊员 + 备援
  -> 前置联络和集合核验
  -> 到场 -> 院内陪同 -> 完成 / 异常上报
  -> 诊后记录（只限获准内容）-> 账单/回访/售后
```

所有非终态订单由明确的调度人负责，不能靠等待自动派单而无人处理。详见功能规格中的状态机、事件和拒接路径。

## 7. 衡量体系与实验设计

**北极星（验证期）**：**合规完成的真实付费陪诊订单数**，须同时满足“风险筛选通过、有效服务同意、符合范围的履约完成、非虚构/非刷单、账务可核对”。单纯创建订单、营销获客数和浏览量不计。

| 指标 | 精确定义 | 90 天假设门槛（非实测） |
| --- | --- | --- |
| 样本深度 | ≥30 子女、≥15 老人、≥10 候选陪诊员、≥5 机构/现场相关角色访谈 | 完成并有匿名归档 |
| 真实付费订单 | 去重后的真实支付且服务完成订单 | 90 天争取 100–150 单；至少先完成 50 单学习样本 |
| 准时到场率 | 开始服务的签到时间 ≤承诺到场时间的订单 / 应到场订单 | ≥98%，不因“平台改约”粉饰 |
| 平台原因爽约率 | 因人员或平台原因未能服务 / 应履约订单 | ≤2%；重大爽约必须复盘 |
| 安全和授权 | 应筛选订单完成筛选率、应授权记录完整率 | 100%；任何严重越界或泄露为 No-Go |
| 单笔贡献利润 | 实收 - 陪诊员综合工时 - 变动客服/支付/保险准备 - 退款损失 - 已摊 CAC | 稳定为正；长期争取 ≥20% |
| 真实 CAC | 该来源全部有效获客支出 / 新增完成首次付费家庭 | 每来源单列，不能按免费线索计算 |
| 用户满意度 | 完成订单后独立回访，报告 N、回应率、差评分类 | 展示分布，不仅展示 5 星均分 |
| 90 天二次服务率 | 窗口内需要至少两次就医的受访家庭中，再次实际购买的比例 | 按机会人群追踪，不用全部用户分母 |
| 事故、投诉 | 每百单事件率 + 严重级别 + 结案时长 | 每例根因复盘；重大安全事故立即暂停相关场景 |

**数据要求**：分母固定；不混淆取消订单与完成订单；退款在收入中冲减；披露财务口径与 90 天观测窗口。任何未经测量的“高满意度/高复购”不得写进对外销售材料。

### 7.1 经济模型与定价压力测试

采用研究报告的**演示假设**：298 元/单；5.5 小时综合人员占用 ×30 元/小时=165 元；调度 18、保险/安全 6、支付 3、纠纷准备 10、获客 45，贡献 51 元/单。若每月固定成本 30,000 元，需约 589 单/月覆盖固定支出；未包含所有税费、意外重大损失和跨城管理。**不得将该假设写成业绩**。逐单真实工时与 CAC 应替换示例参数。

## 8. 法律、标准、隐私及风险

### 8.1 适用框架

- **GB/T 47801—2026《社会化陪同就医服务 基本要求》**自 2026-11-01 实施，为推荐性国家标准，需作为机构运营、合同、收费、服务过程、人员和质量的规范参照（见调研 [26]–[29]）。
- 地方配套规定、机构备案、劳动/灵活用工合规、职业责任保险、消费者权益、个人信息处理规则，须对试点城市逐项法律审查。上海 2026 方案仅属地方样本（见 [30]）。
- 陪诊不构成医疗执业许可。对陪诊员的培训或技能证明不得宣传为国家统一医疗职业资格。
- 《个人信息保护法》下，健康信息属于敏感个人信息；应以最小必要、透明告知、合法处理基础、必要时单独同意、严格访问控制和可删除为前提；老人已撤回共享，不得继续向家属推送健康信息。

### 8.2 对产品影响最大的禁止事项

1. 不诊断、不解读检验报告、不建议调整药物或治疗方案。
2. 不代签医疗文书、不代替本人/法定代理人作医疗决定。
3. 不违规代抢号、倒卖号源，不承诺医院特权。
4. 未获院方允许与当事人恰当同意，不录音录像诊室，不默认上传完整病历至第三方模型。
5. 没有真正书面合作关系时，不宣称平台为“某医院官方指定”。
6. 不让自动化流程覆盖人工风险否决或紧急升级。

### 8.3 安全响应原则

分级结果应是“适合标准陪诊 / 人工确认后决定 / 不承接并转介”三种产品处理结果，**不是疾病严重程度诊断**。现场出现失去意识、急性胸痛、呼吸困难、跌倒伤害等紧急征象时由现场人员立即寻求医院/急救帮助并依法依规联系 120，通知平台应急负责人及授权联系人；订单状态改为安全事件，不得要求陪诊员继续常规工作流。必须在上线前完成桌面推演与真人演练。

### 8.4 安全与数据设计（P0）

- 服务对象资料按最小必要收集，默认不采集病历扫描件；诊后记录与行政节点分开存储。
- `service_consent`、`data_processing_notice`、`family_share_consent` 版本化、时间戳与撤回操作分开留痕。
- 支付者、服务对象、陪诊员、客服、调度、管理员采用最小权限；任何角色访问敏感数据都需服务关联和审计。
- 传输/静态加密、后端权限校验、短期受控访问、脱敏日志、最小保存期与删除/备份清理机制。
- 发生事故优先安全处置和法定/合同义务；审计留存不得被普通订单删除绕过。

## 9. 交付计划与责任分工

| 时间窗（假设） | 主要交付物 | 进入下一阶段的条件 |
| --- | --- | --- |
| W1–2 需求与合规 | 访谈、落地城市政策核验、合同/隐私/保险初审、院区 SOP | 老人/家属真实痛点与风险边界确认 |
| W3–4 人工试点 | 核验小型人员池，人工接单/派单、纸面或合规电子授权 | 完成至少 10 单低风险试履约，无流程失控 |
| W5–8 数字 MVP | 订单、授权、排班、节点、异常、客服、审计 | 端到端 E2E、权限与安全演练通过 |
| W9–12 受控扩展 | 持续付费订单与回访、单位经济模型、Go/No-Go 决策 | 原始订单记录、成本台账与安全审查可复核 |

**责任角色**：产品经理对范围和指标负责；试点运营经理对人员/排班/现场 SOP 负责；法务/隐私负责人审核合同和数据流程；医疗行业顾问审核非医疗服务边界与转介；工程负责人保障安全与可靠性；客服质检负责人闭环纠纷。若没有相应专业人员参与，不能用软件上线代替治理。

## 10. 上线标准（Go / No-Go）

**Go（需全部满足）**：试点城市及服务合同经法律顾问审查；人员身份、培训、保险适用范围完成核查；全流程可留存本人同意与分享授权；高风险筛选有人工否决；两人以上可接管紧急事件；资费与取消机制公开；权限与数据删除测试通过；无未关闭 P0/P1 安全缺陷；至少一次现场突发演练；成本按实际工时核算。

**No-Go（任一触发）**：严重医疗越界、未经授权共享健康信息、重大泄露、无法响应紧急事件、无法保障人员到场、合法履约依赖不当号源交易，或商业模型在合理定价与真实成本下持续负贡献。发现严重风险时立即暂停相关场景、完成调查整改后再复评。

## 11. 待决事项与下一步调查

1. 首个城市和医院片区：医院是否允许第三方陪诊？是否存在登记、陪同人数限制或实际操作规则？
2. 老人身份和授权：哪些情况下需要监护或法定代理人，如何验证并处理代签争议？
3. 付款与退改：押金/预收款与服务时长、加时计费、改派/迟到费用如何公平披露？
4. 保险与用工：人身意外、职业责任、交通、重大事件中保险到底覆盖什么？人员与平台是什么法律关系？
5. 数据保存：实际必要的最短保存期、纠纷举证、删除权和审计义务怎样平衡？
6. 市场入口：社区/养老机构导流的合法性、反商业贿赂边界、真实获客成本。
7. 多病共存：哪些“看似常规的复诊”实则风险过高，需要服务前二次人工核验？
8. 谁付费：成年子女、老人本人、社区或商保，不同支付方是否需要不同产品与合同。
